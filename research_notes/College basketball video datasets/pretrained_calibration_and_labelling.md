# Pretrained models, code and semi-automatic methods for basketball court calibration / landmark labelling (as of 2026-11-02)

Scope note: research was done by web search plus fetching primary pages (arXiv, GitHub READMEs, challenge PDFs, tool docs). Several Roboflow Universe dataset pages, the MDPI multi-sport paper and a Theseus thesis returned HTTP 403 to the fetcher, so facts about them come only from search snippets and are flagged as such. "Verified" below means the fact was read on the primary page; "claim" means it was read in a search snippet or secondary source only.

## Key question 1: Which basketball court-calibration weights are actually downloadable, under what licence, and what footage were they trained on?

### Takeaway
Only one peer-reviewed basketball calibration model has public code with a stated licence (KaliCalib, CeCILL 2.1, trained on the DeepSportradar/Keemotion FIBA-court dataset, not TV broadcast); everything else that is downloadable is hobbyist YOLO-pose weights or Roboflow Universe projects of unverified provenance and mixed licences. No released weights were found that were trained on NCAA footage, and the only published college-basketball calibration dataset (Stats Perform, CVPR 2020) was never released with code.

### Cited Findings
- KaliCalib (Maglo, Orcesi, Pham; CEA, ACM MMSports 2022) code is at github.com/CEA-LIST/KaliCalib under the CeCILL 2.1 licence; README names two provided checkpoints, `model_test.pth` and `model_challenge.pth`, reports test-model MSE of 107.78 mm and challenge-model MSE of 73.16 mm, and trains on the MMSports 2022 camera-calibration challenge dataset (verified from README; download links for the .pth files were not visible in the fetched README text) — [CEA-LIST/KaliCalib](https://github.com/CEA-LIST/KaliCalib); third-party metadata also lists licence cecill-2.1, 15 stars, 9 forks — [code.gouv.fr mirror](https://ecosystem.code.gouv.fr/hosts/GitHub/repositories/CEA-LIST%2FKaliCalib/readme)
- KaliCalib architecture: ResNet-18 U-Net style encoder-decoder with dilated convs and non-local blocks, heatmaps at 1/4 resolution for K=91 perspective-aware sampled court keypoints plus 2 basket heatmaps, ~14.5M params, ~9 ms/image on a GTX 1080 Ti; augmentation = horizontal flip p=0.5 and colour jitter (brightness 0.7, contrast 0.5, saturation 0.5, hue 0.5) — [KaliCalib ar5iv](https://ar5iv.labs.arxiv.org/html/2209.07795)
- KaliCalib training data: DeepSportRadar Basketball Instants Dataset, 480 train / 164 val / 84 test / 84 challenge images; images come in pairs (one per half court), random crops generate the splits; the paper says the training set lacks a wide variety of arenas and images were taken from the centre of the court — [KaliCalib ar5iv](https://ar5iv.labs.arxiv.org/html/2209.07795)
- The DeepSportradar camera-calibration challenge dataset is 728 image + calibration pairs (480/164/84), "views generated from original cameras of the Keemotion system" of FIBA-court games; test arenas KS-FR-CAEN, KS-FR-LIMOGES, KS-FR-ROANNE; challenge images provided at 960x540; annotations are calib3d Calib objects (K, R, T), not homographies; dataset is downloaded from Kaggle (`deepsportradar/basketball-instants-dataset`); no licence is stated on the README page — [DeepSportradar/camera-calibration-challenge](https://github.com/DeepSportradar/camera-calibration-challenge)
- DeepSportradar baseline: DeepLabv3 segments 20 court lines, intersections are matched to 3D court points and `cv2.calibrateCamera` is run; falls back to mean training camera if fewer than 5 intersections; metric is MSE (cm) of projecting 6 image points to the court — [DeepSportradar/camera-calibration-challenge](https://github.com/DeepSportradar/camera-calibration-challenge); baseline scored 592.48 cm MSE on the test set — [KaliCalib arXiv PDF](https://arxiv.org/pdf/2209.07795v1.pdf)
- Sha et al. (Stats Perform, CVPR 2020) "End-to-End Camera Calibration for Broadcast Videos" introduces "a new college basketball dataset" and a pipeline of court segmentation, template-based pose estimation and a spatial-transformer homography refinement; the CVF PDF returned 403 to the fetcher and no code or dataset download was found in searches; SOTAVerified lists the paper's reproduction status as "Unverified" with no linked implementation — [CVF PDF](https://openaccess.thecvf.com/content_CVPR_2020/papers/Sha_End-to-End_Camera_Calibration_for_Broadcast_Videos_CVPR_2020_paper.pdf); [SOTAVerified](https://sotaverified.org/papers/end-to-end-camera-calibration-for-broadcast); related Stats Perform patents on calibrating a broadcast feed exist — [USPTO 11861806](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/11861806)
- Hobbyist weights: abdullahtarek/basketball_analysis (MIT licence) ships a YOLOv8-pose `court_keypoint_detector.pt` via a Google Drive link; the README does not state keypoint count, training image count, footage source or accuracy — [abdullahtarek/basketball_analysis](https://github.com/abdullahtarek/basketball_analysis). Forks (castlehill00, zostaff, Manishmaurya89, Wasim7x) reuse the same weights; moorexavierb/CourtVision trains its own `court_keypoints.pt` with 18 landmarks and includes the training notebook; cs25m116's project uses a 33-landmark model loaded through Roboflow with an API key (claims from search snippets) — [moorexavierb/CourtVision](https://github.com/moorexavierb/CourtVision); [cs25m116 repo](https://github.com/cs25m116/Basketball-Player-Detection-Tracking-Identification)
- Roboflow's official RF-DETR keypoint fine-tuning tutorial uses the public Universe dataset `roboflow-jvuqo/basketball-court-detection-2` (version 19, COCO keypoint export) with 33 landmarks on a single "court" class; training recipe 576 px, 50 epochs, batch 2 with grad-accum 2, lr 1e-4, on a Colab T4; the model is RF-DETR Keypoint Preview (Apache 2.0); the page tests on "NBA broadcast footage" but does not state image count, licence or footage source of the training set, and reports no final OKS/mAP number — [Roboflow blog](https://roboflow.com/blog/train-rf-detr-keypoint); same dataset is used in the RF-DETR cookbook — [rfdetr cookbook](https://rfdetr.roboflow.com/develop/cookbooks/fine-tune_keypoints/)
- Other Roboflow Universe basketball court projects found by search (claims; pages returned 403): `nbavision/court-detection-2` (listed CC BY 4.0), `vayvay/basketball_keypoint_detection`, `val-aospz/court-keypoint`, `segmentation-datasets/basketball_court_segmentation` (261 images, instance segmentation), `zy-vevvi/nba_court_segmentation` (3 classes: basketball-court, paint, three-point-line) — [Universe search results](https://universe.roboflow.com/nbavision/court-detection-2); [basketball_court_segmentation model page](https://universe.roboflow.com/segmentation-datasets/basketball_court_segmentation/model/2/documentation)
- No Hugging Face model for basketball court keypoints/segmentation was found; the closest HF model is a YOLO11m fine-tune for ball/player/referee detection trained on a single university game, whose card warns it may not generalise across teams, camera perspectives or lighting — [HF 446f6e6e79/YOLO-basketball-fineTuned](https://huggingface.co/446f6e6e79/YOLO-basketball-fineTuned)
- A 2025 Theseus thesis (Trinh) paired a pretrained Roboflow court-keypoint model with single-view homography to map shot locations and reports that amateur footage with poor line visibility, camera motion and occlusion degraded homography stability (claim from search snippet; page 403) — [Theseus](https://www.theseus.fi/handle/10024/909540)
- A 2023 Rokken Inc. paper (Hua et al., 39th Fuzzy System Symposium) detects 33 basketball court keypoints, trained on a Blender-rendered synthetic set; >80% keypoint accuracy on synthetic images but the model "was not able to generalize to real-world images"; no weights mentioned — [J-STAGE](https://www.jstage.jst.go.jp/article/fss/39/0/39_453/_article/-char/en)

### Inferences
- The 33-landmark schema (used by the Roboflow tutorial dataset, the Rokken synthetic work and the cs25m116 project) appears to be a de facto community standard for basketball court keypoints; adopting it keeps the option of fine-tuning from any of these sources.
- KaliCalib weights are the only ones with a documented training domain and licence, but the domain (Keemotion fixed/auto-production cameras at centre court, FIBA courts, 3 French arenas in test) differs from NCAA TV broadcast (NCAA court markings, moving broadcast camera, varied arenas), so a domain gap should be expected; the paper itself flags limited arena variety.
- CeCILL 2.1 is a GPL-compatible copyleft licence; fine for personal/research use, but derivative distribution must stay CeCILL/GPL.

### Gaps
- Could not confirm whether KaliCalib's .pth checkpoints are actually downloadable (README says "provided" but no link was visible in the fetched text); needs a clone/inspection of the repo or its releases.
- Image count, licence and footage source (NBA vs college vs FIBA) of `roboflow-jvuqo/basketball-court-detection-2` could not be read (page 403). Same for `nbavision/court-detection-2` and `vayvay/basketball_keypoint_detection`.
- No quantitative accuracy exists for any hobbyist YOLO-pose court weights.
- Sha et al. 2020 reported numbers on college basketball could not be read (PDF 403); the dataset appears never to have been released.

## Key question 2: Do any soccer field-registration codebases accept an arbitrary court template so a basketball court model can be plugged in? Which report cross-sport results?

### Takeaway
None of the open soccer codebases (PnLCalib, NBJW, TVCalib, KpSFR, Jiang et al., Chen & Little) documents a swappable sport template; all hard-code a soccer pitch model and ship soccer-only weights. The only published cross-sport frameworks (Nie et al. WACV 2021, five sports incl. basketball; the MDPI 2025 multi-sport homography paper) have no official code, and KaliCalib is effectively Nie et al. re-implemented for basketball.

### Cited Findings
- PnLCalib (Gutiérrez-Pérez & Agudo): code GPL-2.0-or-later, weights CC BY 4.0 (release v1.0.0: SV_kp, SV_lines, MV_kp, MV_lines plus WC14/TSWC/WorldPose fine-tunes); README states base models were trained on SoccerNet-Calibration under a since-expired research agreement and contain no footage; pipeline "leverages a 3D soccer field model and a predefined set of keypoints"; no mention of other sports or of how to swap the template — [mguti97/PnLCalib](https://github.com/mguti97/PnLCalib); paper — [arXiv 2404.08401](https://arxiv.org/abs/2404.08401v5)
- No Bells Just Whistles (NBJW, same authors): weights for SoccerNet-pretrained keypoint and line models at GitHub release v1.0.0; keypoints are generated from SoccerNet annotations using pitch geometric properties (line extraction, ellipse fitting, hierarchical keypoint sets); README does not name the pitch-model file nor say the pitch model can be swapped; licence file exists but its type was not visible in the fetched page — [mguti97/No-Bells-Just-Whistles](https://github.com/mguti97/No-Bells-Just-Whistles)
- TVCalib (Theiner & Ewerth, WACV 2023): MIT licence; pretrained segmentation model `train_59.pt` hosted on tib.eu; pipeline = semantic segmentation of pitch segments, point selection, camera-parameter optimisation with a segment reprojection loss and self-verification threshold; README refers only to a 3D/2D "pitch model" and covers soccer only — [MM4SPA/tvcalib](https://github.com/MM4SPA/tvcalib); paper — [arXiv 2207.11709](https://arxiv.org/pdf/2207.11709)
- KpSFR (Chu et al., CVSports 2022): MIT licence; weights `kpsfr.pth` (WorldCup) and `kpsfr_finetuned.pth` (TS-WorldCup, 3,812 time-sequence images from 43 videos of the 2014/2018 World Cups); README says inference currently works only on WorldCup and TS-WorldCup test sets; template layout not specified — [ericsujw/KpSFR](https://github.com/ericsujw/KpSFR)
- Jiang et al. "Optimizing Through Learned Errors" (WACV 2020, Sportlogiq): weights (initial-guess net + loss-surface net) for soccer only via Google Drive; training code not released; soccer template generated by Processing code in repo; licence is non-commercial academic research only, method is patent-pending, commercial licensing via Sportlogiq — [vcg-uvic/sportsfield_release](https://github.com/vcg-uvic/sportsfield_release)
- Chen & Little "Sports Camera Calibration via Synthetic Data" (CVSports 2019): BSD-2-Clause repo; synthetic training data generated by `generate_train_data.py` (example uses 10K cameras); README reports refined-homography mean IoU 0.948 / median 0.964 on the soccer WorldCup test set; the paper also reports results on a volleyball dataset; the pose engine has "only three significant free parameters" — [lood339/SCCvSD](https://github.com/lood339/SCCvSD); [ar5iv 1810.10658](https://ar5iv.labs.arxiv.org/html/1810.10658)
- Nie, Chen, Hamid (Amazon Prime Video, WACV 2021) "A Robust and Efficient Framework for Sports-Field Registration": uniform grid of keypoints over the whole field plus dense field features from a multi-task network; built a dataset "SportsFields" from 192 video clips across five sports including ice hockey and basketball; claims SOTA accuracy in real time on HD; no official code release found — [Amazon Science PDF](https://cdn.amazon.science/2c/75/0f3bbae44ac7aed02c700bed0694/a-robust-and-efficient-framework-for-sports-field-registration.pdf); [WACV 2021 page](https://openaccess.thecvf.com/content/WACV2021/html/Nie_A_Robust_and_Efficient_Framework_for_Sports-Field_Registration_WACV_2021_paper.html)
- KaliCalib is explicitly "built on Nie et al. (2021) without the homography refinement"; KaliCalib's reimplementation of Nie et al. keypoints-only scored 259.90 cm MSE on the DeepSportradar test set vs KaliCalib's 126.61 cm — [KaliCalib ar5iv](https://ar5iv.labs.arxiv.org/html/2209.07795)
- "Symmetric Model for Predicting Homography Matrix Between Courts in Co-Directional Multi-Frame Sequence" (MDPI Symmetry 2025, 17(6):832) covers ice hockey, basketball and handball and aims to work with limited annotation (claim from search snippet; page 403) — [MDPI](https://www.mdpi.com/2073-8994/17/6/832)
- "Can Geometry Save Central Views for Sports Field Registration?" (arXiv 2504.20052, Apr 2025) proposes a bottom-up geometric approach deriving points/lines from circle correspondences, complementary to learned detectors; abstract names no sport and no code link was present — [arXiv 2504.20052](https://arxiv.org/abs/2504.20052)
- SoccerNet 2025 had no standalone calibration challenge; calibration was a sub-task of Game State Reconstruction, where "popular approaches involved landmark detection followed by posterior calibration or homography estimation, with pipelines such as NBJW, PnLCalib, and Broadtrack commonly used", plus optical-flow temporal smoothing; GSR-3 used a custom RT-DETR detecting 27 field-line categories with 16 points each then PnLCalib; GSR-13 initialised from NBJW and tracked keypoints with Lucas-Kanade optical flow — [SoccerNet 2025 results PDF](https://arxiv.org/pdf/2508.19182)
- Last standalone SoccerNet calibration challenge (2023): dataset 25,506 images and 226,305 annotated polylines, 2,690-image challenge set; metric = accuracy@5px x completeness; leaderboard: Sportlight 0.55 (ACC@5 73.22, completeness 75.59), Spiideo 0.53 (52.95 / 99.96), SAIVA 0.53 (60.33 / 87.22), BPP 0.50, ikapetan 0.43, NASK 0.41, MA & JT 0.41, baseline 0.08 (13.54 / 61.54); the winner used an HRNetV2-w48 heatmap network for keypoints (incl. 8 tangent points and 13 homography-projected points) and 23 lines (two-peak heatmaps), then OpenCV calibration on heuristically selected subsets with reprojection-error voting — [SoccerNet 2023 results PDF](https://arxiv.org/pdf/2309.06006)

### Inferences
- Every open soccer codebase reduces to: (a) a template file defining 2D/3D landmark coordinates and line/circle segments, (b) a heatmap detector trained to those landmarks, (c) a PnP/homography solver. Steps (a) and (c) are sport-agnostic in principle; the practical cost of retargeting is rewriting the template definition (and any soccer-specific heuristics such as ellipse fitting for the centre circle) and retraining (b) from scratch with basketball labels, because no soccer weights transfer. TVCalib (MIT) and NBJW/PnLCalib (GPL/CC-BY) are the most permissively licensed starting points; Jiang et al. is non-commercial and patent-encumbered.
- The grid-keypoint idea (Nie et al. / KaliCalib) is the published approach with demonstrated basketball results and should be preferred over corner-only schemas for a sparse-marking court.

### Gaps
- Could not read any repo's template definition file to confirm how hard swapping to a basketball court is; a code-level inspection (e.g., TVCalib's pitch model module, NBJW `utils/`) is needed.
- No cross-sport numbers from Nie et al. (the paper PDF was not fetched); SportsFields dataset release status unknown.
- MDPI 2025 multi-sport paper: datasets, numbers, code availability unread (403).

## Key question 3: What accuracy do these methods achieve on broadcast basketball, per published numbers?

### Takeaway
The only public, directly comparable basketball numbers are from the MMSports 2022 / DeepSportradar benchmark (fixed Keemotion cameras, not TV broadcast): KaliCalib reaches ~107-127 cm MSE on the 6-point court-projection metric vs 592 cm for the line-segmentation baseline, with 76.5% of frames under 1 m error. No published reprojection-error or projected-court-IoU figures were found for NCAA or NBA broadcast footage from any open model.

### Cited Findings
- DeepSportradar/MMSports 2022 metric: MSE (cm) of re-projecting six frame points (bottom of frame) onto the court plane vs ground truth — [KaliCalib arXiv PDF](https://arxiv.org/pdf/2209.07795v1.pdf); [challenge repo](https://github.com/DeepSportradar/camera-calibration-challenge)
- Results on that benchmark: challenge baseline 592.48 cm; Nie et al. reimplementation (keypoints only) 259.90 cm; KaliCalib best 126.61 cm (test) and 140.14 cm (challenge set); 76.5% of per-image test MSEs below 1 m; no homography produced for 2 test images; ablation gains: colour jitter ~18%, random flips ~30%, perspective-aware sampling ~30%, basket localisation ~3% — [KaliCalib ar5iv](https://ar5iv.labs.arxiv.org/html/2209.07795); the current README reports 107.78 mm (test model) and 73.16 mm (challenge model) — [CEA-LIST/KaliCalib](https://github.com/CEA-LIST/KaliCalib)
- Unit caveat: the paper reports cm (126.61 cm) while the README reports mm (107.78 mm); both numbers are the same order of magnitude in cm if the README unit is a typo for cm, but this was not resolvable from the sources — [KaliCalib ar5iv](https://ar5iv.labs.arxiv.org/html/2209.07795) vs [CEA-LIST/KaliCalib](https://github.com/CEA-LIST/KaliCalib)
- Oo et al., "A Residual Attention-based EfficientNet Homography Estimation Model for Sports Field Registration" (MMSports 2022) evaluates on World Cup 2014 and a "National Basketball" dataset (claim from search snippet; numbers not read) — [ResearchGate](https://www.researchgate.net/publication/375706881_A_Residual_Attention-based_EfficientNet_Homography_Estimation_Model_for_Sports_Field_Registration)
- Soccer reference points for what "good" looks like: Jiang et al. whole-field IoU mean 0.902 / median 0.925 after optimisation on 186 WorldCup test images, ~1.56 s/image — [sportsfield_release](https://github.com/vcg-uvic/sportsfield_release); Chen & Little mean IoU 0.948 / median 0.964 — [SCCvSD](https://github.com/lood339/SCCvSD); SoccerNet 2023 best ACC@5px 73.22% (Sportlight) — [SoccerNet 2023 results](https://arxiv.org/pdf/2309.06006)
- Roboflow's RF-DETR keypoint tutorial shows loss and `val/keypoint_map_50_95` curves for the 33-point basketball dataset but prints no final number — [Roboflow blog](https://roboflow.com/blog/train-rf-detr-keypoint)
- Classical line-based approaches: a Stanford CS231A project on NBA broadcast frames notes that white-pixel line-candidate methods "break down for basketball, since line colors aren't regulated and vary by venue", and uses a court-colour mask + Hough transform instead (no quantitative accuracy) — [Stanford CS231A](https://stanford.edu/class/cs231a/prev_projects_2015/basketball.pdf)

### Inferences
- A ~1 m court-plane error (KaliCalib median regime) is adequate for shot-chart zones and coarse possession location but marginal for fine player-tracking metrics; broadcast footage with zoom/pan and more arena variety is likely to be worse, not better, than the fixed-camera benchmark.
- Because no open model reports numbers on broadcast NCAA/NBA frames, any chosen model must be validated on a small hand-labelled college set (which doubles as the fine-tuning set).

### Gaps
- No published IoU or reprojection numbers for any open method on NBA or NCAA broadcast video; Sha et al. 2020 (college dataset) numbers unread.
- Official MMSports 2022 calibration leaderboard (other teams' scores) not found; KaliCalib numbers are self-reported.
- Oo et al. 2022 basketball numbers not read.

## Key question 4: What is the fastest credible path to ~200-500 labelled college frames?

### Takeaway
Documented evidence favours manual landmark clicking with a fixed skeleton template plus model-assisted correction in a second pass: Roboflow Annotate and CVAT both support a named 33-point court skeleton with per-point occluded/outside flags and COCO-keypoint export, CVAT additionally supports skeleton tracks over video and model-driven skeleton pre-annotation; Label Studio has keypoints but no skeleton/edge template or direct COCO export. Pure synthetic pretraining (Blender) has one documented basketball attempt that failed to transfer to real images, so synthetic data is at best a pretraining supplement, and a small real set is still required.

### Cited Findings
- Roboflow keypoint projects start from a skeleton (point names + edges, one per object type) built in the Skeleton Editor; points can be marked occluded; export is COCO Keypoint JSON; in the basketball tutorial each of the 33 points is placed "at the same geometric location across frames" with visibility flags visible / occluded (hidden but geometrically known) / skipped (off-screen) — [Roboflow keypoint launch blog](https://blog.roboflow.com/keypoint-detection-on-roboflow/); [edit keypoint skeletons docs](https://docs.roboflow.com/annotate/edit-keypoint-skeletons); [RF-DETR keypoint tutorial](https://roboflow.com/blog/train-rf-detr-keypoint)
- Roboflow Label Assist pre-labels with a foundation model, a previous trained version, or a starred Universe model; docs say it is "currently supported on select project types" and describe only boxes and polygons (mask output), with no mention of keypoint/skeleton pre-labelling — [Roboflow model-assisted labeling docs](https://docs.roboflow.com/annotate/model-assisted-labeling)
- CVAT skeletons: built in the Configurator (points + edges, optional background image), templates downloadable/uploadable as SVG; per-point Outside / Occluded / Hidden properties (Outside and Occluded are saved); skeletons can be annotated in Track mode on video; export to CVAT-for-images and COCO Keypoints; auto-annotation via AI Tools > Detectors with per-point mapping review — [CVAT skeleton docs](https://docs.cvat.ai/docs/annotation/manual-annotation/shapes/skeletons/); CVAT supports model integration for automatic skeleton detection (e.g., 133-point COCO WholeBody) — [CVAT blog](https://cvat.ai/blog/cvat-auto-annotation-skeletons); LearnOpenCV notes keypoint-tool interpolation works for single points only, while the skeleton tool works from a predefined label set suited to repetitive jobs — [LearnOpenCV](https://learnopencv.com/a-closer-look-at-cvat-perfecting-your-annotations/)
- Label Studio: `KeyPointLabels` tag for named points and `KeyPoint` tag for unlabeled points; ML-assisted labeling via `smart`/`smartOnly` (release 1.3.0 sends a keypoint to a model to get a mask back); community thread states there is no configurable object-based keypoint grouping (no skeleton); MMPose docs say Label Studio cannot directly export COCO keypoint format and a conversion script is needed — [Label Studio keypoint template](https://labelstud.io/templates/image_keypoints.html); [KeyPointLabels tag](https://labelstud.io/tags/keypointlabels); [release 1.3.0](https://labelstud.io/blog/release-130.html); [community thread](https://community.labelstud.io/t/multi-object-in-image-keypoint-labeling-and-export/421); [MMPose Label Studio guide](https://mmpose.readthedocs.io/en/latest/user_guides/label_studio.html)
- Roboflow's sports camera-calibration recipe (soccer): detect a fixed set of 32 pitch keypoints, `cv2.findHomography`, then a ViewTransformer to map player positions; the same code pattern is what the basketball tutorial follows with 33 points — [Roboflow camera calibration blog](https://blog.roboflow.com/camera-calibration-sports-computer-vision/)
- Roboflow RF-DETR keypoint fine-tuning on the 33-point basketball dataset runs on a free Colab T4 at 576 px, 50 epochs, batch 2 x grad-accum 2 — [Roboflow blog](https://roboflow.com/blog/train-rf-detr-keypoint)
- KaliCalib trained a usable model from only 480 training images (644 with val) using heavy augmentation; the authors say the small training set "lacks a wide variety of arenas" and relied on flips, colour jitter and perspective-aware keypoint sampling to compensate — [KaliCalib ar5iv](https://ar5iv.labs.arxiv.org/html/2209.07795)
- Jiang et al. evaluated on only 186 soccer test images and ship a `world_cup_data_augmentation` folder plus an H5 test set, illustrating the scale of per-sport data used in that line of work — [sportsfield_release](https://github.com/vcg-uvic/sportsfield_release)
- Synthetic basketball: Rokken Inc. (2023) rendered a Blender basketball court dataset with 33 keypoint labels per image; the model exceeded 80% keypoint accuracy on synthetic images but did not generalise to real images, and the authors conclude labelled real data is required for fine-tuning — [J-STAGE](https://www.jstage.jst.go.jp/article/fss/39/0/39_453/_article/-char/en)
- Synthetic soccer/volleyball: Chen & Little generate training data by sampling camera parameters (pose engine with three significant free parameters) and rendering the template edge image, with strong WorldCup results (mean IoU 0.948) — [SCCvSD](https://github.com/lood339/SCCvSD); [ar5iv 1810.10658](https://ar5iv.labs.arxiv.org/html/1810.10658)
- NBA2K dataset (Zhu et al., ECCV 2020 "Reconstructing NBA Players"): 27,144 poses across 27 subjects captured from NBA2K19, each frame with RGB image, 3D pose, meshes/textures and a 4x4 camera projection matrix (`proj_mat.npy`); access by Google Form; licence CC BY-NC-SA 4.0; real current NBA players excluded for copyright reasons — [NBA2K-dataset GitHub](https://www.github.com/luyangzhu/NBA2K-dataset); [arXiv 2007.13303](https://arxiv.org/pdf/2007.13303); [project page](https://grail.cs.washington.edu/projects/nba_players)
- SoccerNet 2025 GSR entries propagated calibration temporally with optical flow (Lucas-Kanade on NBJW keypoints and auxiliary points; BroadTrack parameters propagated from multiple stable frames) — [SoccerNet 2025 results PDF](https://arxiv.org/pdf/2508.19182)

### Inferences
- Fastest credible path for 200-500 college frames: (1) define a 33-point court skeleton (compatible with the Roboflow tutorial dataset) in Roboflow Annotate or CVAT; (2) hand-click ~100-150 diverse frames (different arenas, camera zooms, both halves); (3) fine-tune RF-DETR-keypoint or a YOLO-pose model on those plus the public 33-point Universe data if its licence allows; (4) run the model over the remaining frames and correct in the annotator (CVAT supports model-driven skeleton pre-annotation natively; Roboflow Label Assist is not documented for keypoints, so pre-labels would be uploaded as COCO JSON). With per-frame homography fitting, the expected effort is dominated by the first manual pass; KaliCalib's result from 480 images suggests this size is sufficient for a single-domain model if augmentation is strong.
- Temporal propagation (optical flow of keypoints across a broadcast clip, as in SoccerNet 2025 GSR entries, or CVAT skeleton tracks) reduces the number of frames that need independent clicking when frames are sampled from the same clip; combined with a court-line edge-fit refinement this mimics "template propagation".
- Synthetic rendering (Blender, or NBA2K projection matrices) is reasonable only as a pretraining/augmentation source; the one documented basketball sim-to-real attempt failed without real fine-tuning data.

### Gaps
- No documented end-to-end workflow specifically for a ~200-frame basketball landmark dataset was found (people publish models, not labelling diaries); time-per-frame estimates are therefore unavailable.
